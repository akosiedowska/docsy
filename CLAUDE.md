# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Docsy is a medical appointment booking app. Two independent npm projects (no workspaces): `backend/` (Fastify + Prisma + PostgreSQL) and `frontend/` (React + Vite). The root `package.json` only provides Prettier (`npm run format -- <paths>`; config in `.prettierrc`). There are no tests yet.

## Commands

Backend (run from `backend/`):

- `npm run db:up` / `db:down` — start/stop the Postgres container (port **5433**, via root `docker-compose.yml`)
- `npm run prisma:migrate` — `prisma migrate dev`; `prisma:generate`, `prisma:seed`, `prisma:studio`
- `npm run dev` — `tsx watch src/server.ts`, API on `http://localhost:3000`

Frontend (run from `frontend/`):

- `npm run dev` (port 5173), `npm run build` (`tsc -b && vite build`), `npm run lint`

Setup: copy `backend/.env.example` and `frontend/.env.example` to `.env` (`DATABASE_URL`, `JWT_ACCESS_SECRET`, `VITE_API_URL`).

## Backend architecture

- Entry: `src/server.ts` registers Zod type provider, error handler, CORS (hardcoded origin `http://localhost:5173`, credentials on), `@fastify/jwt`, cookies, then `src/routes/index.ts`.
- Feature modules live in `src/modules/<name>/` (`*.routes.ts` → `*.controller.ts` → `*.service.ts`, plus `*.schemas.ts` and optional `*.policy.ts`); layering rules are in `.claude/rules/coding-standards.md`.
- Auth middleware chain (`src/middleware/`): `authenticate` verifies the JWT, loads the user from the DB and sets `request.currentUser` (typed in `src/types/fastify.d.ts`). `requireRole(...roles)` does role gating. `authorize(policy)` does resource-level checks: a policy supplies `getResource` + `isAllowed` (see `appointment.policy.ts`). Compose them in `preHandler: [authenticate, ...]`.
- Auth model: short-lived access token (JWT, held in memory on the client) + refresh token in a cookie; exactly one `Session` row per user (`userId` unique, stores `tokenHash`; refresh tokens are not rotated — see migrations). Refresh endpoint is `/auth/refresh`.
- Data model (`prisma/schema.prisma`): `User` (role `PATIENT | DOCTOR | ADMIN`) with optional `Doctor`/`Patient` profile; `Doctor` → `Slot[]` → `Appointment` ← `Patient`. Prisma client is generated to `backend/generated/prisma` and uses the `@prisma/adapter-pg` driver adapter.

## Frontend architecture

- Routing is **TanStack Router, file-based** (not React Router, despite the README). Route files live in `src/routes/`; `src/routeTree.gen.ts` is generated by the Vite plugin. `routes/_auth.tsx` is the guard layout: it awaits `authBootstrapPromise` (`features/auth/bootstrap.ts`, which restores the session via refresh) and redirects to `/` if unauthenticated. `src/app/router.ts` calls `router.invalidate()` whenever `isAuthenticated` changes in the Zustand store. `src/pages/` holds page components that the thin route files render, grouped by role (`pages/patient|doctor|admin/`).
- Role-based routing: under `_auth`, pathless layout routes gate by role via `requireRole(...)` from `features/auth/guards.ts` (redirects to `/dashboard` on mismatch): `_auth/_patient` (`/reservation`), `_auth/dashboard/_doctor` (`/dashboard/schedule`), `_auth/dashboard/_admin` (`/dashboard/doctors`). `/dashboard` itself (`dashboard/index.tsx`) renders a different dashboard page per role. Path constants live in `src/app/paths.ts` (typed against the generated route tree).
- Auth state: `src/stores/authStore.ts` (Zustand). `src/api/client.ts` is the shared Axios instance (`withCredentials`, bearer token from store); on a 401 it does a single-flight `/auth/refresh` and retries once, otherwise clears the session and hard-redirects to `/`.
- Features are in `src/features/<name>/`; feature structure, forms, and UI library conventions are in `.claude/rules/coding-standards.md`.
- UI: Mantine theme in `src/styles/theme.ts`, `colors.ts`. Layout shells are in `src/layouts/` and `src/components/layout/` (Header, BottomNav, Sidebar). `AppLayout` shows a collapsible Sidebar only for non-patient roles (links per role in `src/app/sidebarLinks.ts` → `staffNav`); patients get the BottomNav on mobile.
- Doctor/admin dashboards, `/dashboard/schedule` and `/dashboard/doctors` are placeholder stubs (no UI or API hooks yet); only patient flows are implemented.

## Coding rules

Coding conventions (formatting, naming, backend layering, auth middleware, Prisma, routing, TanStack Query, Mantine) are in `.claude/rules/coding-standards.md`. It is path-scoped and loads automatically when working on `backend/src`, `backend/prisma`, or `frontend/src` files.

## Implementation Process — Plan & Questions First

- Before writing any code, produce a short **Implementation Plan**:
  - Goal, main steps, affected files.
- **Ask clarifying questions** when the task is ambiguous:
  - Stop after asking — do **not** begin implementation.
  - End the response with: `Awaiting your answers…`
  - Only proceed after answers are provided in the next message.
