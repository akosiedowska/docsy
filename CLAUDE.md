# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Docsy is a medical appointment booking app. Two independent npm projects (no workspaces): `backend/` (Fastify + Prisma + PostgreSQL) and `frontend/` (React + Vite). The root `package.json` only provides Prettier (`npm run format -- <paths>`; config in `.prettierrc`). There are no tests yet.

## Commands

Backend (run from `backend/`):
- `npm run db:up` / `db:down` — start/stop the Postgres container (port **5433**, via root `docker-compose.yml`)
- `npm run prisma:migrate` — `prisma migrate dev`; `prisma:generate`, `prisma:seed`, `prisma:studio`
- `npm run dev` — `tsx watch src/server.ts`, API on `http://localhost:3000`

Frontend (run from `frontend/`):
- `npm run dev` (port 5173), `npm run build` (`tsc -b && vite build`), `npm run lint`

Setup: copy `backend/.env.example` and `frontend/.env.example` to `.env` (`DATABASE_URL`, `JWT_ACCESS_SECRET`, `VITE_API_URL`).

## Backend architecture

- Entry: `src/server.ts` registers Zod type provider, error handler, CORS (hardcoded origin `http://localhost:5173`, credentials on), `@fastify/jwt`, cookies, then `src/routes/index.ts`.
- Feature modules in `src/modules/<name>/` follow a fixed layering: `*.routes.ts` (schemas + preHandlers) → `*.controller.ts` → `*.service.ts` (Prisma access), with `*.schemas.ts` (Zod, used for request validation and response serialization) and optional `*.policy.ts`.
- Auth middleware chain (`src/middleware/`): `authenticate` verifies the JWT, loads the user from the DB and sets `request.currentUser` (typed in `src/types/fastify.d.ts`). `requireRole(...roles)` does role gating. `authorize(policy)` does resource-level checks: a policy supplies `getResource` + `isAllowed` (see `appointment.policy.ts`). Compose them in `preHandler: [authenticate, ...]`.
- Errors: throw the classes in `src/errors/http-error.ts`; `middleware/error-handler.ts` maps them to responses.
- Auth model: short-lived access token (JWT, held in memory on the client) + refresh token in a cookie; exactly one `Session` row per user (`userId` unique, stores `tokenHash`; refresh tokens are not rotated — see migrations). Refresh endpoint is `/auth/refresh`.
- Data model (`prisma/schema.prisma`): `User` (role `PATIENT | DOCTOR | ADMIN`) with optional `Doctor`/`Patient` profile; `Doctor` → `Slot[]` → `Appointment` ← `Patient`. Prisma client is generated to `backend/generated/prisma` (import from there, not `@prisma/client`) and uses the `@prisma/adapter-pg` driver adapter. After editing the schema run `prisma:migrate`, which also regenerates the client.

## Frontend architecture

- Routing is **TanStack Router, file-based** (not React Router, despite the README). Route files live in `src/routes/`; `src/routeTree.gen.ts` is generated by the Vite plugin — don't edit it. `routes/_auth.tsx` is the guard layout: it awaits `authBootstrapPromise` (`features/auth/bootstrap.ts`, which restores the session via refresh) and redirects to `/` if unauthenticated. `src/app/router.ts` calls `router.invalidate()` whenever `isAuthenticated` changes in the Zustand store. `src/pages/` holds page components that the thin route files render, grouped by role (e.g. `pages/patient/`).
- Auth state: `src/stores/authStore.ts` (Zustand). `src/api/client.ts` is the shared Axios instance (`withCredentials`, bearer token from store); on a 401 it does a single-flight `/auth/refresh` and retries once, otherwise clears the session and hard-redirects to `/`.
- Features are in `src/features/<name>/` (`api.ts`, `hooks/` wrapping TanStack Query, `queryKeys.ts`, `components/`, `schemas.ts`/`types.ts`). Forms use React Hook Form + Zod.
- UI: Mantine (theme in `src/styles/theme.ts`, `colors.ts`) with CSS modules for layout components. `@mui/material` is also installed but Mantine is the primary library. Layout shells are in `src/layouts/` and `src/components/layout/` (Header, BottomNav, Sidebar — the sidebar is for staff roles).
- Role-based UI is in progress on branch `feat/add-roles`: the patient pages exist; routes/sidebar for doctor/admin are being added.
